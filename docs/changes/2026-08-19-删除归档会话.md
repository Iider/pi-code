# 2026-08-19 删除归档会话

## 需求

归档会话只能恢复不能删除，长期堆积无法清理。需要在归档列表中支持单个删除和按工作区全部删除，删除前弹确认框，样式对齐官方 WebUI 原生弹窗。

## 方案与关键决策

- 采用方案：服务端新增 `DELETE /api/v1/sessions/:id`，仅允许删除已归档且空闲的会话；前端两个载体（webapp 源码、冻结版 WebUI 适配脚本）各自接入。
- 原因：归档文件一旦删除不可恢复，服务端把关归档状态比前端自查更可靠；当前线上跑的是 `webui/dist` 冻结版，必须通过适配脚本注入交互，webapp 源码作为协议参考实现保持同步。
- 否决方案：复用归档/恢复的 POST action 路由，原因：删除是破坏性操作，独立的 DELETE 语义和 409 冲突响应更清晰。

## 改动内容

- `server/src/bridge.ts`：新增 `deleteArchivedSession()`，校验归档与空闲状态后删除会话文件和元数据；`setMeta()` 抽出 `persistMeta()` 复用。
- `server/src/routes.ts`：新增 DELETE 路由，未找到返回 404，未归档或忙返回 409。
- `webapp/`：`KimiWebApi` 增加 `deleteSession()`，工作区状态组合式函数和设置页接入单个/全部删除，复用全局 `ConfirmDialog`；新增 trash 图标与中英文案。
- `webui/adapter/model-config/`：适配脚本加载归档会话列表，按工作区行匹配注入删除按钮和「全部删除」，确认弹窗样式对齐原生 `ui-dialog`（遮罩、按钮、间距全部使用设计令牌）。
- `server/test/session-routes.test.ts`：补充 DELETE 路由回归测试。

## 业务流程变化

1. 归档列表每行「恢复」左侧出现删除图标，工作区行末尾出现「全部删除」。
2. 点击后弹出确认框，说明删除范围且不可恢复；确认后逐个调用 DELETE 接口。
3. 服务端删除会话 JSONL 文件与元数据，前端移除对应行，空工作区卡片整体移除。
