# Agent 回复引用第一阶段

## 变更

- 在已完成 Agent 回复的底部、复制按钮右侧新增“引用这条回复”操作。
- 点击后在输入区展示独立的引用 chip；静止输入框不显示原回复或内部标记。
- 发送时使用 `[quote]` 短指纹；引用源位于最近一次上下文压缩之前时使用 `[quote:excerpt]` 有界摘录。
- 已发送用户消息将兼容信封折叠为只读引用 chip；撤回编辑时会恢复引用 chip 与正文。
- 根据首次页面反馈，将草稿 chip 移入输入框卡片，统一为文件附件的单行尺寸，并取消引用图标强调色。
- 调整文件附件 chip 的左侧留白，取消图标向胶囊边缘的负偏移。
- 引用与普通文件共用同一附件行，并以文件 chip 为准统一圆角和内边距。
- 补齐冻结版 WebUI 依赖的文件上传与读取接口；发送普通文件时只给 Agent 提供本地文件路径，避免把完整文件重复塞入上下文。

## 边界

- 未修改服务端、Pi Agent 或官方哈希 bundle；仍复用官方 WebUI 原生提交、排队、附件与鉴权链路。
- 热路径最多 48 个 Unicode 字素，冷路径最多 256 个 Unicode 字素；不复制完整 Agent 回复，不调用模型生成摘要。
- 单条引用、浏览器适配层实现；多引用和跨客户端精确回跳留待验收后评估。

## 验证

- adapter 构建、JavaScript 语法检查、13 个服务端测试文件共 86 项测试、TypeScript 类型检查、构建产物一致性检查与 `git diff --check` 均通过。
- 已使用真实 multipart 请求验证文件上传接口返回文件 ID、名称、媒体类型和大小。
- 浏览器视觉与真实会话链路待用户验收。
