# 2026-08-19 撤回会话消息

## 需求

官方 WebUI 用户消息上的「撤回编辑」按钮和 `/undo` 命令点击后报错 `Unsupported session action: undo`，撤回功能不可用。预期行为：撤回后该轮对话从记录中移除，原文和附件回到输入框等待重新编辑。

## 方案与关键决策

- 采用方案：服务端实现 `POST /api/v1/sessions/{id}:undo`，从当前分支叶子向上找到倒数第 N 条用户消息，调用 Pi SDK 官方的 `AgentSession.navigateTree()` 把叶子指针移到该消息的父节点。
- 原因：`navigateTree` 是 SDK 提供的会话树导航能力，撤回后自动同步 `agent.state.messages` 和上下文，bridge 的历史读取本来就跟随叶子指针，前端协议（`:undo` + snapshot 重同步 + 文本回填输入框）也是现成的，服务端是唯一缺口。
- 否决方案：物理重写会话文件删除被撤回的条目，原因：违背 SDK 只追加设计，有损坏风险；撤回后继续发消息会形成新分支，旧分支自然退出历史，无需物理删除。

## 改动内容

- `server/src/bridge.ts`：新增 `undoSession()` 和 `SessionNothingToUndoError`；校验会话空闲后按 `count` 定位目标用户消息并 `navigateTree`。
- `server/src/routes.ts`：action 路由新增 `undo` 分支，支持 `{count}` 请求体；409 忙碌提示从 fork 专用措辞改为按 action 描述。
- `server/test/session-routes.test.ts`、`server/test/integration.test.ts`：补充 undo 路由单测和端到端集成测试；MockAgentSession 增加 `navigateTree` 模拟实现。

## 业务流程变化

1. 用户点「撤回编辑」或输入 `/undo`，前端调用 `:undo` 并重新同步 snapshot。
2. 服务端把会话树叶子撤回到目标用户消息的父节点，该轮对话离开活跃分支。
3. 前端将被撤回消息的文字和附件回填到输入框，用户修改后重发即形成新分支。

## 验证方式

- 服务端：12 个测试文件、84 项测试通过；TypeScript 类型检查通过。
- 页面验收：撤回后错误提示消失，该轮对话从记录移除，原文回到输入框。
