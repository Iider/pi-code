# 2026-08-19 修复 Web 交互与模型配置

## 需求

- Web 模式页面无法正常进入，加载层出现错误品牌。
- 工作区“展开更多 / 收起”没有产生可见变化。
- 供应商保存两个模型后，重新打开仍显示旧模型，主页面也未同步。

## 方案与关键决策

- 非 ASCII 客户端标识和凭据在进入 HTTP Header 或 WebSocket 子协议前清理，避免传输层初始化失败。
- 会话分页在工作区过滤后应用 `before_id`，未知游标返回空页，避免重复第一页。
- 内置供应商的完整表单保存为同 ID 本地配置；WebUI 将配置模型数组视为白名单。Pi SDK 对内置模型采用合并语义，直接依赖底层结果会保留未选择模型，因此未采用该方案。
- Windows 跳过不支持的目录句柄 `fsync`，文件句柄仍先同步再原子替换；不降低支持目录同步的平台的持久性保证。

## 改动内容

- `webapp/src/api/config.ts`、`webapp/src/api/daemon/serverAuth.ts`：过滤非法本地连接标识和凭据。
- `webui/adapter/pi-code-brand.css`、`webui/dist/pi-code-brand.css`：Web 模式统一显示 Pi Code 加载品牌。
- `server/src/routes.ts`、`server/test/session-routes.test.ts`：补齐工作区会话游标分页及回归测试。
- `server/src/models/configuration-service.ts`：保存内置供应商覆盖配置，规范化模型 ID，并统一过滤供应商与模型视图。
- `server/src/models/models-config-store.ts`：兼容 Windows 目录同步行为。
- `server/test/configuration-service.test.ts`、`server/test/models-config-store.test.ts`：覆盖内置供应商保存和跨平台存储行为。

## 业务流程变化

1. 供应商编辑器提交完整模型列表。
2. 服务端写入本地覆盖配置并刷新共享模型运行时。
3. 供应商详情、模型接口和主页面选择器使用同一模型白名单。
