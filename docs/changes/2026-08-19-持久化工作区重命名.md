# 2026-08-19 持久化工作区重命名

## 需求

工作区重命名后刷新页面不应恢复为项目路径；新工作区默认显示对应目录的文件夹名称。

## 方案与关键决策

- 采用方案：服务端按工作区根目录保存自定义名称，默认名称取目录最后一级；前端继续保存按根目录索引的本地覆盖。
- 原因：目录根路径在工作区 ID 派生和会话加载之间保持稳定，服务端持久化可覆盖正常注册工作区，前端覆盖可兼容旧服务和派生工作区。
- 否决方案：只在前端保存名称，原因：换浏览器或清理本地存储后名称会丢失；只改默认名称，原因：无法保留用户主动设置的名称。

## 改动内容

- `server/src/bridge.ts`：默认名称改为目录名，新增工作区名称文件读写。
- `server/src/routes.ts`：工作区列表读取持久化名称，重命名接口校验工作区并保存名称。
- `webapp/src/composables/client/useWorkspaceState.ts`、`webapp/src/lib/storage.ts`：按根目录保留名称覆盖，兼容旧服务和派生工作区。
- `server/test/session-routes.test.ts`、`server/test/workspace-name.test.ts`、`webapp/test/workspace-state.test.ts`：补充默认名称和刷新后保留名称的回归测试。

## 业务流程变化

1. 服务端加载工作区时，以目录最后一级作为默认显示名。
2. 用户重命名后，服务端将名称写入 `~/.pi/agent/workspace-names.json`。
3. 前端按工作区根目录应用本地覆盖，刷新或服务重启后仍显示自定义名称。
